# 온이 AI MVP 개발 안내

MVP는 Minimum Viable Product, 즉 핵심 가치를 실제로 확인할 수 있는 최소 기능 제품이다. 이번 MVP는 **고민 입력 → 공감 또는 정책 안내 → 근거 확인**을 끝까지 연결한다. 음성은 글 입력을 돕고, 일정은 캘린더에 연결할 초안까지만 만든다.

작업 위치는 `1104-kimjiwoo` 로컬 브랜치다. 최신 `main` 내용을 로컬 브랜치에 반영한 기존 앱을 바탕으로 AI 기능을 추가하며, GitHub 원격 푸시나 PR 병합은 하지 않았다.

## 1. 기술 선택과 이유

| 사용하는 것 | 하는 일 | 선택한 이유 |
| --- | --- | --- |
| Java 17 + Spring Boot | 요청 검증, 판단 기준 적용, 정책 조회, 대화 보관, Gemini 호출 | 팀의 기존 Java 백엔드와 합칠 수 있다. |
| Gradle wrapper | 의존성 관리, 실행, 테스트 | 프로젝트에 포함된 버전을 사용하므로 전역 Gradle 설치가 필요 없다. |
| React + JavaScript + Vite | 채팅, 출처 카드, 음성 입력, 일정 초안 표시 | 기존 프런트 화면과 같은 기술을 사용한다. |
| H2 메모리 DB (`oni` 프로필) | 로컬 시연용 대화 저장 | MySQL 계정이나 인증서 없이 흐름을 확인할 수 있다. 재시작하면 초기화된다. |
| Gemini REST API | 공감 답변과 검색 자료를 설명하는 문장 생성 | Java HTTP 클라이언트로 호출할 수 있어 Python 서버가 필요 없다. |
| 규칙 기반 데모 제공자 | 외부 호출 없이 고정 기준에 따른 시연 답변 | 키가 없어도 UI와 서버 흐름을 검증할 수 있다. 실제 AI라고 표시하지 않는다. |
| VS Code + Java 확장 | Java·React 코드 편집, 실행, 디버깅 | 한 편집기에서 두 프로젝트를 다룰 수 있다. |

초기 정책 검색에는 별도의 벡터 DB나 모델 학습을 사용하지 않는다. 검토한 소수의 자료를 서버에서 선택하는 것으로 시작한다. 자료가 많아진 뒤 검색 방식을 교체할 수 있다.

## 2. VS Code에서 실행하기

### 준비

1. JDK 17과 프로젝트 프런트 의존성이 요구하는 Node.js를 준비한다. 프로젝트의 Gradle toolchain은 Java 17이다.
2. `RE-Mind.code-workspace`를 VS Code에서 연다. 저장소 루트 폴더를 직접 열어도 된다.
3. 추천 확장에 나타나는 [Extension Pack for Java](https://marketplace.visualstudio.com/items?itemName=vscjava.vscode-java-pack)를 설치한다. 이미 있으면 다시 설치할 필요 없다.
4. Java 프로젝트 가져오기가 끝날 때까지 기다린다. 명령 팔레트의 `Java: Configure Java Runtime`에서 프로젝트 JDK를 확인한다. 컴퓨터별 JDK 절대 경로는 공유 설정에 넣지 않았다.

### 키 없이 시연

`.env`가 없어도 기본 제공자는 `demo`다. AI 시연에는 Aiven MySQL 설정이 필요 없다. 반드시 `oni` 프로필로 실행한다.

VS Code의 `Terminal → Run Task`에서 다음 작업을 실행한다.

1. 처음 한 번 `온이: 프런트 의존성 설치` (`npm ci`).
2. `온이: 백엔드 실행` (`./gradlew bootRun --args=--spring.profiles.active=oni`).
3. 별도 터미널에서 `온이: 프런트 실행` (`npm run dev`).

프런트 터미널에 표시되는 로컬 주소를 연다. 기본 주소는 `http://localhost:5173`이고, 온이 대화 모드에 바로 들어가려면 `http://localhost:5173/#/chat-modes`를 연다. 프런트의 `/api` 요청은 Vite 프록시를 통해 `http://localhost:8080`으로 전달된다.

백엔드 `oni` 프로필은 루프백 주소에 바인딩하는 로컬 시연용이다. AI 컨트롤러도 `oni` 프로필에서만 활성화하며, 일반 `dev`·`prod` 실행에서는 `/api/ai` API를 제공하지 않는다. 익명 시연 API를 운영 서비스의 로그인 API처럼 노출하지 않기 위해서다.

터미널로 실행해도 된다. macOS/Linux에서 저장소 루트를 기준으로:

```bash
sh scripts/start-backend.sh
```

별도 터미널에서:

```bash
cd frontend
npm ci
npm run dev
```

`start-backend.sh`는 `JAVA_HOME`이 지정되어 있으면 그 설정을 사용한다. 미지정 상태의 macOS에서는 설치된 JDK 17을 탐지한다. 설치 프로그램을 자동 실행하거나 사용자의 Java 설정을 변경하지 않는다. Gradle 캐시는 기본적으로 Git에서 제외된 `.local-gradle/`에 둔다.

Windows에서는 VS Code 작업 또는 `backend` 폴더의 `gradlew.bat bootRun --args=--spring.profiles.active=oni`를 사용한다.

### Java 디버깅

`Run and Debug`에서 **온이 API 디버그 (oni)** 를 선택하고 F5를 누른다. `com.remind.RemindApplication`을 시작한다. 같은 포트의 백엔드가 이미 실행 중이면 먼저 해당 터미널에서 Ctrl+C로 종료한다. 일반 실행과 디버그 실행은 둘 중 하나만 사용한다.

### 실제 Gemini로 변경

기본 데모는 외부 AI 호출이 없다. 실제 연결을 시도하려면 저장소 루트의 `.env.example`을 `.env`로 복사한 뒤 AI 항목을 설정한다.

```properties
ONI_AI_PROVIDER=gemini
GEMINI_API_KEY=발급받은_키
GEMINI_MODEL=gemini-3.1-flash-lite
```

백엔드를 다시 시작한다. `.env`는 Java 설정 파일 형식으로 읽으므로 `export`나 값의 바깥 따옴표를 붙이지 않는다. 키를 React 코드나 `VITE_*` 변수에 넣지 않는다. `.env`는 Git 추적 대상에서 제외되어 있다.

`GET /api/ai/config`의 `configured`는 키가 설정되어 있는지 알려준다. 키의 유효성, 모델 접근 권한, 잔여 할당량까지 검증했다는 의미는 아니다. 실제 응답은 요청을 보내 확인해야 한다. `gemini`를 선택하고 키를 넣지 않으면 일반 AI 요청에 오류를 반환하며, 데모 답변으로 대체하지 않는다.

[Gemini 공식 약관](https://ai.google.dev/gemini-api/terms)에 API 사용자 18세 이상 및 대상 이용자 제한이 있고, 무료 서비스에는 민감한 정보·기밀·개인정보를 제출하지 말라는 조건이 있다. **이번 로컬 시연은 가상 보호자와 가상 상황만 사용한다.** 실제 보호자 상담 서비스를 운영하기 전에는 이용 조건, 데이터 처리, 로그인과 접근 통제 등을 별도로 설계해야 한다. 의료 진단·치료 조언 기능으로 제공하지 않는다.

## 3. 요청 한 번이 처리되는 과정

```text
React 입력창
  → POST /api/ai/chat
  → Java가 입력과 세션 소유권 확인
  → 제공자가 의도·검색어를 제안
  → Java 판단 규칙이 허용할 행동 결정
  → 필요한 정책 자료·일정 초안 준비
  → 데모 제공자 또는 Gemini가 답변 작성
  → 대화 기록 저장
  → 답변·출처·일정 초안을 각각 화면에 표시
```

Gemini 모드에서는 모델을 최대 두 번 호출한다. 첫 호출은 의도와 정책 검색어를 정해진 JSON 형태로 제안하고, 두 번째 호출은 Java가 고른 자료와 판단 결과로 답변을 만든다. 중간에 서버가 정책 검색·일정 초안 도구를 실행한다. 데모 모드에서는 같은 흐름을 고정된 제공자가 대신한다.

Gemini는 자유롭게 서버 기능을 실행하는 주체가 아니다. 이번 MVP의 에이전트는 **모델의 제안을 서버의 판단 기준과 허용된 도구로 제한하는 흐름**이다. 모델이 일정 기록 의도를 추측해도 명시적인 사용자 요청이 없으면 먼저 확인한다. 무제한으로 모델과 도구를 반복 호출하는 루프도 없다.

명백한 위험 표현을 서버 규칙이 감지한 경우에는 외부 AI 호출 없이 정해진 안전 확인 문구를 제공할 수 있다. 이 응답의 `provider`는 `safety-rules`로 표시한다. Gemini 실패 시 일반 대화를 데모로 대체하는 동작과는 별도로 설계한 경로다.

이렇게 나누는 이유는 AI가 “등록했습니다”라고 문장을 만들었다는 이유로 실제 일정이 생기거나, AI가 만들어낸 주소를 정책 출처로 표시하는 일을 방지하기 위해서다.

## 4. 판단 기준은 코드에 어떻게 들어가는가

핵심 개념을 줄여 표현하면 다음과 같다. 실제 규칙은 백엔드 `com.remind.ai` 패키지에서 관리한다.

```java
// 개념 설명용 코드: 판단 → 자료 준비 → 답변 생성 순서를 분리한다.
Plan plan = gateway.plan(message, mode, history);
Decision decision = decisionEngine.decide(message, mode, plan.intent(), plan.safety());
List<Policy> sources = selectAllowedPolicies(decision, message, plan.policyQuery());
Proposal draft = createDraftOnlyWhenRequested(decision, message);
Answer answer = gateway.answer(contextWith(decision, sources, draft));
return responseWith(answer, decision, sources, draft);
```

| 기준 | 기대하는 동작 | 목적 |
| --- | --- | --- |
| 위급하거나 위해 의도가 드러난 표현 | 일반 답변보다 안전 확인을 우선 | 위기 표현을 일반적인 정책 질문처럼 처리하지 않는다. |
| 명시적인 일정 기록 요청 | 제목·날짜·시간을 추출하고 부족한 항목 표시 | 고민을 실제 일정으로 단정하지 않는다. |
| 직전 일정 초안 뒤에 날짜·시간만 답함 | 이전 초안의 누락 항목을 제한적으로 보완 | “내일이에요”, “오후 3시요” 같은 짧은 후속 답변을 처리한다. |
| 지원·서비스·신청 관련 질문 | 서버에 등록된 관련 자료를 선택 | 정책명을 모델의 기억에만 의존하지 않는다. |
| 공감 모드의 감정 표현 | 조언을 밀어붙이지 않는 답변 | 사용자가 선택한 대화 방식을 따른다. |
| 정보 부족 또는 지원하지 않는 요청 | 필요한 정보 질문 또는 한계 설명 | 추측을 사실처럼 전달하지 않는다. |

규칙은 지원하는 표현에 대한 제한 장치이며, 한국어 전체의 의미를 정확하게 분류하는 완성된 판별기가 아니다. 표현을 놓치거나 잘못 분류할 수 있어 테스트 사례로 계속 보완해야 한다. 임상 평가나 우울증 판정에 사용하지 않고, 진단명·우울증 확률을 출력하지 않는다. 판단 이유는 개발용 접기 패널에서 확인할 수 있다.

정책은 `backend/src/main/resources/ai/policies.json`의 6개 안내 자료에서 최대 3개를 키워드로 선택한다. 가족교실·자조모임·힐링프로그램·동반치매환자보호서비스·방문요양·주야간보호를 다룬다. 지자체별 운영 자료나 현금 지원액은 아직 포함하지 않는다. `region`을 입력해도 해당 지역의 운영 여부를 확인한 것은 아니다.

정책 자료의 지역·대상 조건이 충분하지 않으면 개인의 수급 자격을 확정하지 않는다. 출처와 확인 날짜는 서버 자료를 사용하며, 확인 날짜가 있다고 이후 변경까지 자동 반영되는 것은 아니다. 운영 전에는 자료 갱신 절차가 필요하다.

## 5. 화면과 서버가 주고받는 규격

### 대화 보내기

`POST /api/ai/chat`

```json
{
  "conversationId": null,
  "requestId": "새로 생성한 UUID",
  "mode": "SOLUTION",
  "message": "방문요양 지원제도를 어디서 알아볼 수 있을까요?",
  "region": "서울"
}
```

- 새 대화는 `conversationId`를 생략하거나 `null`로 보낸다. 이어가는 대화는 서버가 반환한 ID를 보낸다.
- `requestId`는 화면에서 `crypto.randomUUID()`로 생성한다. 같은 전송을 재시도할 때는 동일한 ID를 사용해 중복 저장을 막는다. 다른 내용에 같은 ID를 쓰면 충돌로 처리한다.
- `mode`는 `EMPATHY` 또는 `SOLUTION`이다. 메시지는 공백만 있는 값이 아닌 1~2,000자이며, 지역은 선택 항목으로 최대 50자다.
- 응답의 `reply`, `sources`, `scheduleProposal`, `decision`, `provider`, `demo`를 별도로 사용한다. 답변 문장 안의 특정 단어로 저장 동작을 실행하지 않는다.

### 다른 API

| API | 용도 |
| --- | --- |
| `GET /api/ai/config` | 데모/실제 제공자와 설정 상태 확인 |
| `GET /api/ai/conversations` | 현재 세션의 대화 목록 |
| `GET /api/ai/conversations/{id}` | 현재 세션 소유 대화의 메시지와 응답 카드 복원 |
| `DELETE /api/ai/conversations/{id}` | 현재 세션 소유 대화 삭제 |

이 MVP는 브라우저의 서버 세션 쿠키로 임시 사용자를 구분한다. 운영 서비스의 로그인 인증을 구현한 것은 아니다. 다른 세션 소유 대화는 조회·삭제할 수 없고, 서버를 재시작하면 H2 데이터와 세션이 초기화된다. 사용자 ID를 요청 헤더에 임의로 넣어 권한을 얻는 방식은 사용하지 않는다.

### 오류

응답 형태는 `{ "code": "오류종류", "message": "화면용 설명", "retryable": false }`다.

| 상태 코드 | 의미 |
| --- | --- |
| 400 | 잘못된 입력 |
| 403 | 허용되지 않은 Origin에서 변경 요청 |
| 404 | 대화 없음 또는 해당 세션에서 접근 불가 |
| 409 | 요청 ID 재사용 충돌 또는 대화 모드 충돌 |
| 429 | 세션 요청·대화 개수·대화 길이 한도 또는 제공자 사용 한도 |
| 502 / 503 | 제공자 응답 실패·연결 실패·키 미설정 등 |
| 500 | 그 밖의 내부 처리 오류 |

현재 시연 한도는 세션당 분당 요청 12회, 대화 20개, 한 대화의 요청·응답 쌍 80개다. Gemini의 별도 할당량도 적용된다.

실패를 성공 답변으로 포장하지 않는다. 화면에서 오류를 표시하고 다시 시도할 수 있게 한다. 로그에 API 키나 사용자의 원문 대화를 남기지 않는다.

## 6. 음성과 일정의 정확한 범위

음성 입력은 브라우저 `SpeechRecognition` 또는 `webkitSpeechRecognition` 지원 여부를 확인해 사용한다. 인식한 글을 입력창에 넣고 사용자가 확인한 다음 전송한다. 미지원, 권한 거부, 인식 오류 시 글 입력을 계속 사용할 수 있다.

[MDN 문서](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)에 따르면 브라우저 지원이 제한되어 있고, Chrome 등에서는 음성을 외부 인식 서비스로 전송할 수 있다. 오프라인 음성인식이나 음성이 기기에만 남는다고 보장하지 않는다. 실제 마이크와 브라우저 권한은 시연 기기에서 확인해야 한다.

일정 응답의 `scheduleProposal.saved`는 항상 `false`다. 제목, 날짜, 시간, `Asia/Seoul` 시간대, 누락 항목을 표시한다. 현재 초안 파서는 병원·치매안심센터 방문, 상담, 검사, 약 복용, 운동, 산책 같은 한정된 제목을 처리한다. 오늘·내일·모레 또는 연도가 포함된 날짜를 사용하며, 오전/오후가 없는 “3시”는 시간 정보가 부족한 것으로 처리한다. “오후 3시”나 “15:00”처럼 명확히 입력한다.

직전 답변에 일정 초안이 있을 때 “내일”, “오후 3시요”처럼 날짜·시간만 입력하면 기존 초안과 합친다. 잘못된 날짜나 시간으로 정정하면 예전 값을 유지해 확정된 것처럼 보이지 않도록 해당 항목을 비운다. 임의의 여러 문장에서 모든 일정 정보를 누적하거나 자유로운 제목 수정을 처리하는 기능은 아직 없다.

**일정 저장 API는 아직 없고, 병원 예약도 수행하지 않는다.** 추후 팀 캘린더 API가 준비되면 사용자 확인과 중복 방지 검사를 거쳐 연결한다.

## 7. 검증 방법과 완료 기준

백엔드와 프런트 검증은 각각 실행한다.

```bash
cd backend
./gradlew test
```

```bash
cd frontend
npm ci
npm run build
```

VS Code의 `온이: 백엔드 테스트`, `온이: 프런트 빌드` 작업으로도 실행할 수 있다. 자동 테스트에서는 가짜 제공자를 사용해 입력, 의도 분류, 근거 선택, 소유권, 재시도와 오류 처리를 검증한다. 따라서 테스트 통과만으로 실제 Gemini 키나 네트워크 연결까지 검증했다고 해석하면 안 된다.

화면에서는 다음을 확인한다.

| 입력·상황 | 완료 기준 |
| --- | --- |
| “오늘은 이야기만 들어주세요.” | 공감 모드로 답하고 원하지 않는 조언을 쏟아내지 않는다. |
| “방문요양 지원제도를 알려주세요.” | 검토한 정책 자료와 출처가 카드에 표시된다. |
| 확인하지 못한 정책·자격 질문 | 모르는 내용을 단정하거나 지원금을 만들어내지 않는다. |
| “내일 오후 3시 병원 일정을 기록해줘.” | 일정 초안이 보이고 미저장 상태가 명확하다. |
| “병원 일정을 기록해줘.” 다음에 “내일”, “오후 3시요” | 직전 일정 초안에 날짜와 시간을 보완하며 계속 미저장이다. |
| AI 키 없음·네트워크 실패 | 오류를 표시하며 데모로 몰래 전환하지 않는다. |
| 대화 새로고침·삭제 | 같은 세션의 대화 복원·삭제가 동작한다. |
| 다른 브라우저 세션에서 대화 ID 접근 | 다른 세션 대화를 반환하지 않는다. |
| 음성 미지원·권한 거부 | 안내가 보이고 글 입력을 계속 사용할 수 있다. |

실제 Gemini 키가 없는 개발 환경에서는 라이브 Gemini 호출을 검증하지 않았다. 실제 마이크 인식과 권한 승인, 모바일 브라우저 동작도 별도 수동 검증 항목이며 검증을 완료했다고 주장하지 않는다. 자동 검증 결과는 개발 완료 보고에서 구분한다.

## 8. 후속 개발 순서

1. 실제 Gemini 계정 조건과 가상 데이터로 응답 품질 확인.
2. 판단 사례 추가, 공감 말투 조정, 정책 자료 검수와 갱신.
3. 팀의 로그인 사용자 정보 및 영구 DB와 연결.
4. 캘린더 담당자와 API 형식을 맞추고 확인 후 저장 기능 연결.
5. 실제 이용자 대상 데이터 처리·보관·삭제 및 운영 배포 설계.

커뮤니티와 지도는 기존 팀 범위로 두고, 이번 변경은 온이 대화 흐름을 우선한다.
